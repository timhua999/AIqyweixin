## 1 引言

### 1.1 目的

通过企业微信机器人承接询价、轨迹等高频问题，降低人工负荷、提高响应一致性；无法可靠回答的问题进入「未答工单」与改进闭环，并在规则触发时提供**转人工兜底**路径。

### 1.2 范围

**首期（MVP）在范围内：**

- 企业微信消息接入（文本为主）、被动回复、加解密与 access_token 管理。
- 意图路由、违禁品与合规筛查、询价要素抽取与校验、轨迹查询（经内部/物流商 API）。
- 知识库与 RAG 辅助（通用问答与违禁辅助；**价格必须来自 API**）。
- 未回答问题记录与后台可检索/导出（权限受控）。
- 实例级配置：企微、LLM、多物流商适配器、话术、**人工客服路由**。
- **转人工**：在**原群聊会话**内按规则展示指派客服的**名片**，机器人发送的消息中**自动 @** 该客服；若该客服**不在当前群内**，则**邀请其加入群聊**（邀请/名片/@ 的可行性与 msgtype 以《企微接入附录》及对接时企微开放能力为准）。**不采用**「跳转与客服单聊」作为首期兜底主路径。

**首期明确不在范围内：**

- 同一进程/同一库服务多家企业的**多租户 SaaS**（含按 Corp 路由、`tenant_id` 配额等）。
- 图片/文件消息（可列为 OOS 或二期）。
- 物流下单、问题件、运单号映射等（列入路线图，不作为 MVP 验收）。

### 1.3 术语

| 术语 | 说明 |
|------|------|
| 租户（对外商务） | 常指「客户」；技术首期不按多租户建模。 |
| 物流商适配器 | 将统一内部 DTO 映射到各物流商 API 的插件化实现。 |
| 转人工兜底 | 在系统拒答/要素不全/API 失败等条件下，于**当前群**内展示指派客服名片并由机器人 **@** 该成员；不在群则**邀请入群**（不首期依赖单聊跳转）。 |
| 客服路由规则 | 意图 / 部门业务线 / 关键词 → 目标企微 `userid` 的有序规则集 + 默认客服。 |
| staff_org_map | 发言员工企微 `userid` → 客户自定义 `org_unit_code` 的自建映射（可不依赖企微通讯录部门树）。 |
| RAG | 检索增强生成；用于 FAQ、包装要求等，**不得**替代查价 API 输出价格。 |

### 1.4 引用与约束

- 企业微信开放平台：回调、加解密、access_token、消息类型能力以对接时官方文档为准。
- 硬件现实约束：**2C4G** 不适合自托管大参数 LLM + 向量库 + 应用 + 数据库全量常驻；MVP 以**云端 LLM API** 为主，本地轻量编排与存储。

### 1.5 运行环境与配置约定（定稿）

| 项 | 约定 |
|----|------|
| Python | 开发机 **3.13.9**；生产环境使用 **Python 3.13.x**，与开发大版本一致，依赖锁文件交付。 |
| 数据库 | **PostgreSQL** 作为 MVP 主库。 |
| 大模型 | **云上 API**；应用通过可配置项连接兼容 **OpenAI 协议** 的网关，至少包括 **`base_url`（API 根地址）** 与 **`api_key`**，以及模型名、温度、`max_tokens` 等；密钥以环境变量或 `.env` 注入，**不进入版本库**。 |
| 企业微信 | 管理后台配置接收消息 **URL、Token、EncodingAESKey** 等；应用侧配置与之匹配的 `corp_id`、应用 `secret` 等（键名以实现文档为准），同样经环境变量或 `.env` 注入。 |

## 2 角色与用例

### 2.1 角色定义

| 角色 ID | 角色名称 | 描述 |
|---------|----------|------|
| R-EMP | 内部员工 | 主用户；通过企微与机器人**单聊或群聊**发起询价、轨迹、咨询等；**转人工兜底以群聊会话为主场景**（见 FR-3.11）。 |
| R-ADM | 系统管理员 | 维护本实例：企微应用、LLM、物流通道、话术、**客服路由与默认客服**、**澄清轮数上限等对话参数**、知识库与未答工单权限。 |
| R-AGT | 人工客服 | 企微通讯录成员；可被路由命中后在**群内**被 @ 并接待；可按报价/售前/售后分工（由路由规则决定）；可能被**邀请入群**。 |
| R-OPS | 客服/运营 | 处理未答问题、抽检、答案回填知识库或样本库（首期可人工粘贴入库）。 |
| R-WECOM | 企业微信 | 消息通道与身份载体。 |
| R-TMS | 物流业务系统（可插拔） | 经适配器提供查价、轨迹等 API；按实例配置启用。 |

**说明：**「平台超级管理员」仅在将来单机多租户 SaaS 阶段引入，**首期不写进范围**。

### 2.2 用例一览（摘要）

| UC-ID | 名称 | 主要参与者 | 简述 |
|-------|------|------------|------|
| UC-01 | 违禁筛查后询价 | R-EMP, R-TMS, LLM | 自然语言 → 筛查 → 要素抽取 → 查价 API → 结构化回复。 |
| UC-02 | 轨迹查询 | R-EMP, R-TMS | 识别订单号 → 轨迹 API → 状态/节点摘要。 |
| UC-03 | 通用售前/售后问答 | R-EMP, 知识库/RAG | 非结构化咨询，检索辅助回答；边界内需免责声明（若产品定稿）。 |
| UC-04 | 未答记录与转人工 | R-EMP, R-AGT, R-ADM | 触发兜底条件 → 写未答工单 → 在**原群**内发客服**名片**并 **@** 客服；不在群则**邀请入群**（与 FR-3.11 一致）。 |
| UC-05 | 实例与路由配置 | R-ADM | 维护适配器、话术、handoff 规则与 staff_org_map。 |

### 2.3 用户故事与验收要点（场景级）

以下为需求评审用「故事 + 可测要点」；详细 GWT 见第 6 节。

**US-01 询价（违禁通过）**  
*作为* 内部员工，*我希望* 用自然语言询价，*以便* 快速获得可报价渠道的结构化结果。  
**验收要点：** 通过筛查后若要素不全，按模板追问；追问轮次上限为实例可配置项 **`max_clarification_rounds`（记作 N，N≥0）**，默认取值在部署文档中给出；要素齐全则调用查价 API；回复中价格字段**仅来自 API**。

**US-02 询价（违禁不通过）**  
*作为* 内部员工，*当我* 询问含禁运/不合规品类时，*系统应* 不调查价 API，并返回可配置、不泄露内部敏感细节的提示语。

**US-03 轨迹**  
*作为* 内部员工，*我希望* 输入订单号查轨迹，*以便* 了解节点与状态。  
**验收要点：** 订单号格式可按物流商配置校验；不存在/错误码有友好提示。

**US-04 未答与转人工（群内）**  
*作为* 在业务群内提问的内部员工，*当* 系统无法回答或达到澄清轮数上限仍要素不全时，*我希望* **仍在当前群里**看到指派客服的**名片**，并看到机器人** @ 到该客服**，*以便* 同事与客服在同一上下文中衔接。  
**验收要点：** 路由顺序与 FR-3.11 一致；消息在原群内发出且包含对指派成员的 **@**；若指派客服不在群内，系统执行**邀请入群**（成功/失败降级见 FR-3.11）；同会话重复打扰有阈值（见 NFR）。**单聊**中触发兜底的处理见 FR-3.11.8。

**US-05 管理员配置**  
*作为* 系统管理员，*我希望* 维护物流商与客服路由，*以便* 不同意图落到正确成员。  
**验收要点：** 配置错误时有明确诊断（响应不回显密钥）；userid 无效时有降级与日志告警。

## 3 功能需求（编号 FR-3.x）

功能编号与计划文档 **§3** 对齐，便于测试用例 ID 映射（建议格式：`TC-FR-3.x-序号`）。

### FR-3.1 企业微信接入

| ID | 需求描述 |
|----|----------|
| FR-3.1.1 | 系统应能接收企业微信回调消息（**首期：文本**）。 |
| FR-3.1.2 | 实现 URL 校验、消息加解密、被动回复时效内应答策略。 |
| FR-3.1.3 | access_token 应缓存并自动刷新，避免无效请求风暴。 |
| FR-3.1.4 | 应同时支持**单聊**与**群聊**回调与回复；**转人工兜底能力以群聊为交付基线**（见 FR-3.11）。 |

### FR-3.2 对话编排与意图路由

| ID | 需求描述 |
|----|----------|
| FR-3.2.1 | 将用户输入分类为可配置枚举（至少覆盖）：`询价`、`轨迹`、`售前咨询`、`售后问题`、`其他/闲聊/模糊`。 |
| FR-3.2.2 | 模糊意图策略在 SRS 定稿：**澄清一轮**或**直接未答+转人工**二选一。 |
| FR-3.2.3 | 意图结果及可选「部门/业务线」标签应作为客服路由输入（与 FR-3.11 一致）。 |

### FR-3.3 违禁品与合规筛查

| ID | 需求描述 |
|----|----------|
| FR-3.3.1 | 输入：用户原文 + 可选知识库检索片段。输出：`通过` / `不通过` + **可展示给员工**的拒绝原因话术。 |
| FR-3.3.2 | 知识来源：结构化表（违禁清单、反倾销品类、液体/粉末等规则）+ 简短政策说明。 |
| FR-3.3.3 | **不通过时不得调用**查价 API。 |

### FR-3.4 询价要素抽取与校验

| ID | 需求描述 |
|----|----------|
| FR-3.4.1 | 必选字段（MVP 基线，可扩展）：起运地、目的地、是否带电、实重、长宽高、件数；可选：品名/材质、贸易条款、时效要求等。 |
| FR-3.4.2 | 校验：数值范围、单位统一（cm/kg）、件数与体积重逻辑（由业务系统算或机器人算须在接口附录写死）。 |
| FR-3.4.3 | 缺失时列出缺项并以企微可读模板追问；追问轮次上限 **N** 为**实例可配置项** `max_clarification_rounds`（整数 ≥0，含 0 表示不追问仅走后续策略），须在配置清单与环境中可维护。 |

### FR-3.5 内部系统集成（物流商适配器）

| ID | 需求描述 |
|----|----------|
| FR-3.5.1 | 查价、轨迹等能力经 **LogisticsAdapter** 统一入口；入参内部标准 DTO，出参统一展示模型。 |
| FR-3.5.2 | 每适配器可配置：endpoint、鉴权、超时、重试（429/5xx）、请求/响应字段映射。 |
| FR-3.5.3 | 日志策略：是否记录请求体须符合脱敏与安全要求。 |
| FR-3.5.4 | 轨迹订单号格式支持按物流商配置（正则/长度）。 |

### FR-3.6 知识库与模型协同

| ID | 需求描述 |
|----|----------|
| FR-3.6.1 | 知识库内容：违禁规则摘要、线路说明、包装要求、FAQ。 |
| FR-3.6.2 | RAG 用于违禁辅助与通用问答；**查价路径以要素+API 为准**。 |
| FR-3.6.3 | **验收约束：** 任何展示给用户的**价格**必须来源于查价 API，而非模型自由生成。 |

### FR-3.7 未回答问题闭环

| ID | 需求描述 |
|----|----------|
| FR-3.7.1 | 记录字段（最低集）：时间、企微 userId、会话 id、用户原文、识别意图、规则/模型中间摘要、是否已调 API、API 错误信息、处理状态（待处理/已回复/已入库等）。 |
| FR-3.7.2 | 转人工时追加：兜底原因码、`route_rule_id`、指派客服 `userid`；可选：是否已 @、是否已在群内、是否已发起邀请/邀请结果（若技术可统计）。 |
| FR-3.7.3 | 后台：列表筛选、导出、关联标准答案后入库（首期允许人工粘贴）。 |
| FR-3.7.4 | 权限：仅管理员/指定角色可查看全量敏感内容。 |

### FR-3.8 非功能需求（详见第 4 节）

在功能需求中引用：**并发、可用性、安全、合规** 为 MVP 必达项，指标在 4.x 定量或定性定稿。

### FR-3.9 后续扩展（路线图，非首期验收）

下单、问题件、订单号→国际运单号映射等：各自独立 API 与意图；本 SRS 正文仅列标题，不验收。

### FR-3.10 产品化与实例配置

| ID | 需求描述 |
|----|----------|
| FR-3.10.1 | 实例级配置：企微（corp_id、agent_id、密钥、Token/EncodingAESKey、回调说明）、LLM（**`base_url`（API 根）**、**`api_key`**、模型名、温度与 max_tokens 上限；云上调用）、物流通道列表与映射、话术与品牌名、**对话参数**（含 `max_clarification_rounds` / N）、**单聊触发兜底时的降级话术**（见 FR-3.11.8）。 |
| FR-3.10.2 | 管理界面：管理员维护配置、客服路由、知识库、未答工单。 |
| FR-3.10.3 | 交付物：安装文档、默认 docker-compose 或 systemd、配置备份/恢复、升级说明。 |
| FR-3.10.4 | 切换/启用适配器后询价与轨迹命中正确 API；配置缺失或错误时提示明确且**不回显密钥**。 |

### FR-3.11 人工兜底与可配置客服路由

| ID | 需求描述 |
|----|----------|
| FR-3.11.1 | 触发条件（与 3.7 对齐）：无法回答、澄清轮数达到配置上限仍要素不全、API 明确失败或无法报价、及管理员定义的其他条件；**不得**在未触发时频繁打扰（见 NFR 频率阈值）。 |
| FR-3.11.2 | **匹配顺序（定稿建议）：** `关键词`（命中即停）→ `org_unit`（由发言员工 userid 查 staff_org_map，再匹配 org 类规则）→ `意图` → `默认客服`。同层多条规则按 `priority` 数值升序，首条命中生效。 |
| FR-3.11.3 | `handoff_default`：**必填**默认目标 `userid` 列表。 |
| FR-3.11.4 | 规则绑定一个或多个 `userid`；若多人，产品定稿「列表任选」或「主+备」一种。 |
| FR-3.11.5 | 发言员工未出现在 staff_org_map 时：**跳过 org_unit 层**，仅走关键词/意图/默认。 |
| FR-3.11.6 | **群聊会话（首期主路径）：** 在当前群内发送包含指派客服**名片**（或企微允许的等价「联系人/客服」展示形态）的回复；同一条（或同一会话策略规定的）机器人消息中应对指派成员执行 **@**（`@userid` / 文本 mention 等以企微客户端与开放接口为准）。**不**以「打开与客服单聊」作为首期必需能力。 |
| FR-3.11.7 | **成员是否在群：** 系统应在发送前或发送流程中判断指派客服是否已在当前群；若**不在群内**，应调用企微「邀请成员进群」或当前应用类型下**等价的加群/邀请**能力，使客服可进入该群；若因权限、应用类型、客户群类型等**无法邀请**，须向用户展示可配置降级话术，并**记录日志/运维告警**。 |
| FR-3.11.8 | **单聊会话：** 不具备「原群」上下文时，**不**承诺完成群内名片+@+邀请闭环；应返回实例可配置的**降级话术**（例如提示员工到指定业务群重试、或仅记录未答工单），具体文案由 `handoff_dm_fallback_message` 类配置项维护（名称以实现为准）。 |
| FR-3.11.9 | 名片、@、邀请进群所依赖的 **API、权限、msgtype** 以《企微接入附录》调研结论为准；SRS 验收表述为：**在群聊场景下**，员工能在**同一群**内看到指派客服的名片展示、**@** 提醒，且在客服不在群时触发**邀请入群**流程（在接口允许范围内成功，否则满足降级与可观测性）。 |

## 4 非功能需求（摘要）

| NFR-ID | 类别 | 需求描述 |
|--------|------|----------|
| NFR-4.1 | 并发 | 定义预期同时在线会话数、峰值 QPS（例如 5～20），并据此设计单实例 worker 与限流。 |
| NFR-4.2 | 可用性 | 单实例重启策略、健康检查接口。 |
| NFR-4.3 | 安全 | 密钥不入库明文（若仅环境变量则运维侧管控）；HTTPS；企微可信 IP；操作审计。 |
| NFR-4.4 | 合规 | 对话与订单数据保留周期、脱敏规则定稿。 |
| NFR-4.5 | 资源 | 2C4G：不推荐常驻大模型；云端 LLM + 轻量本地服务；可选 Redis/磁盘缓存 token。 |
| NFR-4.6 | 转人工骚扰控制 | 同一会话单位时间内群内「转人工」消息（含名片/@/邀请）触发次数上限为可配置或定稿阈值，避免刷屏。 |

## 5 数据与配置模型摘要（与实现一致）

| 实体 | 用途 |
|------|------|
| org_unit（可选字典） | `code`、`name`、`sort_order`。 |
| staff_org_map | `wecom_userid`、`org_unit_code`、`is_primary`、`enabled`；支持一人多岗多行。 |
| handoff_rule | `rule_id`、`match_type`（keyword \| org_unit \| intent）、`match_value`、`target_userids`、`priority`、`enabled`。 |
| handoff_default | 单例：`default_target_userids`，必填。 |
| 实例参数（示例键名） | `max_clarification_rounds`（N）、`handoff_dm_fallback_message`（单聊兜底话术）等，与 FR-3.4.3、FR-3.10.1、FR-3.11.8 对应；落库或 `.env` 以实现为准。 |

**运行时输入：** 发言员工 `userid`、当前意图、原文（关键词匹配）、**会话类型（单聊/群）与群 id**（若群聊）。**输出：** `target_userids` 列表 → 组装群内名片 + @ + 邀请策略所需载荷；单聊走降级配置。

## 6 验收标准（Given-When-Then）

以下覆盖首期关键验收；测试用例应扩展边界与异常。

### 6.1 违禁与查价

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-01 | 用户问题经筛查判定为不通过 | 用户请求询价 | 系统不调查价 API；返回可配置拒绝话术；无价格字段 |
| AC-02 | 筛查通过且要素齐全 | 用户请求询价 | 系统调用查价 API；展示价格与 API 一致；无 API 来源以外的「报价数字」 |

### 6.2 要素与追问

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-03 | 筛查通过但缺少必选字段；`max_clarification_rounds` = N | 用户询价 | 系统列出缺失项并以模板追问；追问轮次**不超过 N**（N 改配置后回归仍成立） |
| AC-04 | 达到配置追问上限仍不全；会话为群聊 | 用户持续不补全 | 记未答工单；按 FR-3.11 在**原群**触发转人工（若产品选择并行） |

### 6.3 轨迹

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-05 | 订单号合法且轨迹存在 | 用户查轨迹 | 返回节点/状态摘要；数据来自轨迹 API |
| AC-06 | 订单不存在或业务返回无记录 | 用户查轨迹 | 友好提示；不崩溃；可记未答（按规则） |

### 6.4 API 可靠性

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-07 | 查价/轨迹 API 超时或 5xx | 用户触发调用 | 用户收到超时/失败友好提示；日志可诊断；可选重试符合配置 |

### 6.5 未答与后台

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-08 | 任意触发「未答入库」条件 | 对话结束于兜底分支 | 数据库存在记录且字段满足 FR-3.7.1；管理员可检索/导出 |

### 6.6 产品化与适配器

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-09 | 实例启用物流商 A 与 B | 询价与轨迹各测一轮 | 请求命中正确 base_url 与映射；切换配置后行为符合文档 |
| AC-10 | 故意错误企微或 LLM 配置 | 启动或健康检查 | 明确错误信息；**响应/界面不回显密钥** |

### 6.7 转人工路由与群内呈现（与 FR-3.11 一致）

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-11 | 配置：询价→用户 A，售后→用户 B，默认→用户 C；**群聊**会话 | 分别模拟三类意图触发兜底 | 路由目标分别为 A、B、C；回复均发生在**该群**内 |
| AC-12 | 员工 X 在 staff_org_map 标记为 `PRESALES`；存在 org_unit 规则售前→用户 D；群聊 | 员工 X 发言并触发兜底 | 在关键词未更高优先级命中时，应落到售前规则对应客服（如 D） |
| AC-13 | 员工无映射且无意图特殊规则；群聊 | 触发兜底 | 落到默认客服 C |
| AC-14 | 规则中 userid 在企微不存在 | 触发兜底 | 降级提示用户；日志/告警供运维处理 |
| AC-16 | 群聊；路由到客服 A；A **已在群内** | 触发兜底 | 机器人在群内发送含 **A 的名片**（或等价形态）的消息，且内容中对 A 有 **@** |
| AC-17 | 群聊；路由到客服 A；A **不在群内** | 触发兜底 | 系统发起**邀请 A 入群**（在接口与权限允许下成功）；若失败则用户看到配置降级话术且存在日志/告警 |
| AC-18 | **单聊**会话 | 触发兜底 | **不**要求完成群内名片+@+邀请；用户收到配置的 `handoff_dm_fallback_message`（或等价） |

### 6.8 数据隔离（交付形态）

| TC-ID | Given | When | Then |
|-------|-------|------|------|
| AC-15 | 客户甲与客户乙各一套独立部署 | 分别在甲、乙环境操作 | 无共享库/共享进程；不要求同库 `tenant_id` 验收 |

## 7 假设与待决事项（实施前产品定稿）

1. **未命中时是否展示「已记录」**类文案。  
2. **价格与轨迹展示模板**是否强制带免责声明。  
3. **转人工与工单顺序**：先群内转人工再记工单、或并列、或仅工单——话术统一。  
4. **`max_clarification_rounds`（N）的默认值**、**转人工同会话频次阈值** 的默认值（二者均为可配置项时的建议默认）。  
5. 《企微接入附录》中**群内名片、@ 成员、邀请成员进群**所依赖的接口、权限、应用类型限制及降级策略定稿。  
6. **单聊降级话术**默认文案及管理后台是否必填校验。
